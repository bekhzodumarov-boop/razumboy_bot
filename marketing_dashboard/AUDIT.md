## Проверенные детали кода

- `analytics.py`: SQLite журнал с timestamp UTC, user_id, event_id, attempt_id, event_name, step, result, dedup_key, source. Включён с 20.10.2026 по контексту проекта; реальная полнота определяется импортом, старые события не восстанавливаются.
- `/start` и deep links сохраняют traffic_event_id/source. Контракт `event_50` / `event_50_src_instagram` не меняется; неизвестная метка становится unknown.
- После профиля сохраняются только валидные метаданные источника (интеграционный релиз). Перезапуск одной игры сохраняет attempt_source; изменение source в новой ссылке не переписывает активную попытку.
- Завершение фиксируется после записи заявки; повторное подтверждение защищено FSM/проверкой active registration. Один пользователь может иметь заявки на разные игры и отменённые/новые заявки на одну игру; это не надёжная идентичность команды.
- `analytics_report.py`: полуоткрытый интервал и исходы as-of cutoff, назначение игры поздней menu-попытке. `/report ID` агрегирует бизнес-БД отдельно от журнала. Полный ответ функции содержит user_id/attempt_id и НЕ пригоден для публичного API без проекции.
- `registrations`: confirmed/cancelled. Подтверждение числа игроков/declined хранится отдельно в confirmations и не доказывает посещение или оплату.
- Чтение транзакции SQLite удерживает read lock и может задерживать writer в rollback journal. Импортёр работает исключительно с изолированными копиями, timeout 0.2с, короткий SELECT whitelist; не создаёт Database (тот запускает миграции и исторический seed).
- Railway: существующий worker и Volume /data остаются без изменений. Для нового веб-сервиса требуется отдельное хранилище и HTTPS после отдельного согласования; в этой задаче только localhost.

## Архитектура и граница доверия

`изолированная SQLite-копия → локальный CLI exporter → псевдонимизированный JSON → отдельная SQLite приложения ← Meta CSV`.

FastAPI не знает пути рабочей БД и не принимает пути файлов в HTTP. Экспорт явно требует подтверждения isolated-copy и отдельный стабильный HMAC-ключ окружения (не Telegram token). JSON содержит агрегаты регистраций и псевдонимы событий, не телефоны/имена/Telegram ID. Псевдонимы остаются чувствительными внутренними данными и не выдаются API. Импорт одного stream idempotent; полная замена наблюдённого snapshot атомарна, уменьшение истории отклоняется. Не смешивать demo и реальные streams в одном хранилище.

Выбор SQLite: один администратор/один web worker, ручной импорт, отдельный Volume, транзакции и backup API. WAL только в аналитическом хранилище. При нескольких workers, автоматической синхронизации или росте — PostgreSQL с той же моделью событий/импортов. Telegram-worker не импортирует пакет и не получает новых зависимостей.

Meta: только дневные неперекрывающиеся строки. Ключ account/currency/timezone/level/day/campaign/adset/ad; повтор — upsert, исправленные значения обновляются, другие дни не удаляются. Гранулярности campaign/adset/ad не складываются: запрос всегда выбирает один level, timezone и currency. Сумма охвата недостоверна, поэтому не вычисляется. Нельзя сравнивать частично перекрывающиеся дневные окна аккаунтов с разными timezone как точные одинаковые сутки.

## Предложение атрибуции следующего этапа

Новый payload `m_<случайный base64url ID>` ≤64 символов, серверная таблица immutable link ID → game/campaign/adset/ad/placement, active_from/expires_at, разрешённый redirect. ID генерирует администратор, произвольные campaign поля от пользователя не принимаются. Старые event_* ссылки сохраняются с compatibility tests. Дедуп по update/callback; неизвестный/просроченный ID не создаёт рекламную атрибуцию. Хранить first_known и last_known отдельно от immutable attempt attribution; явная связь completed attempt ↔ registration_id необходима для атрибуции игроков. Потребуется отдельный PR бота и разрешение на миграции. Meta clicks и Telegram actions имеют разные системы подсчёта, между ними есть потери.

Справочные контракты: [Telegram deep links](https://core.telegram.org/bots/features#deep-linking), [FastAPI cookies](https://fastapi.tiangolo.com/advanced/response-cookies/), [Vite](https://vite.dev/guide/).
