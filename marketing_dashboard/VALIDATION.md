Все тесты выполняются на синтетических временных SQLite и синтетических credentials. Проверены: числа событий и distinct пользователей; повторные визиты/попытки; открытые формы, отмены, замены, ошибки и отменённые бизнес-заявки; фильтры; позднее назначение игры без утечки будущей истории; полуоткрытый cutoff; текущие бизнес-статусы; невозможность выдумать campaign attribution; недоступные платежи/финансы; отсутствие приватных идентификаторов в API.

CSV: повторный импорт, обновление суммы той же строки без потери остальных дней; отдельные валюты/timezone/levels; дневная схема и дубли; отрицательные/NaN/слишком точные суммы; десятичная запятая; недоступные link clicks и нулевые знаменатели; неаддитивность reach. Snapshot: whitelist, HMAC, старый журнал без source, неизменность хешей источников mode=ro, UTC-вечер → следующий день Ташкента; запрет уменьшать/переписывать историю. Backup отдельной БД: WAL-compatible SQLite Backup API, integrity_check, SHA256 и запрет перезаписи.

API: отказ без входа на data/import/export/session, HTTPS/host/origin, CSRF, logout и отзыв сессии, throttle, лимит upload, атомарный отказ без возврата исходных private полей, нейтрализация CSV-формул, no-store/CSP. Тестовый стек Starlette сообщает предупреждение об устаревании httpx TestClient; проверки проходят с зафиксированными версиями. Это не ошибка runtime-кода; при обновлении тестового стека нужен повторный прогон.

## Что не проверялось на реальных данных

Рабочая копия SQLite, настоящий CSV Ads Manager и разрешение на доступ production не предоставлялись. Поэтому production не читался. Рабочий адаптер к существующей схеме и ручной безопасный импорт готовы; переход к реальным цифрам требует разрешённых изолированных копий, timezone и отдельного stable HMAC key. Подробный порядок — README. Snapshot не является общей атомарной копией двух БД.

## Оставшиеся риски и границы

- Один web worker / один администратор, сессии и rate limit в памяти. Для внешнего многопользовательского сервиса нужны SSO/MFA и устойчивое состояние; HTTPS reverse proxy должен быть настроен отдельно. Сейчас проверен только loopback HTTP, не внешний TLS-хостинг.
- Ограниченный full-snapshot протокол, чтение истории в памяти, предел 100 000 событий / 64 MiB локального файла. Для роста — incremental sync и PostgreSQL.
- Псевдонимы и малые группы чувствительны: нужен закрытый доступ к аналитической БД/backup; API не выдаёт идентификаторы. Названия игр/кампаний контролирует оператор и не должны содержать персональных данных.
- Нет campaign/ad linkage с ботом, registration_id linkage с попыткой, платежей, посещения, team identity и минимального порога. CPL/CAC/ROAS/ROMI/стоимость игрока не выдумываются.
- Журнал неполон до включения аналитики; исходы активности не являются когортной конверсией; текущее состояние заявок нельзя принять за историческую явку.
- Никакого деплоя, merge или изменения production в этом MVP не выполнялось.

Отдельно проверено: хранилище отказывается принимать файлы с таблицами users/events/registrations/funnel_events до любых DDL или записей; SHA256 исходника после отказа не меняется.
